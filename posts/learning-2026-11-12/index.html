2026.11.12学习笔记（Python 卡片回答、任务入队和 JSON）

发表于2026-11-12|更新于2026-11-14|学习笔记

昨天在 agent-autoloop 里体验了回答卡片后任务接着跑。今天我在 PyCharm 新建了练习文件，先用 Python 写卡片回答和入队。这是单独的学习练习，原来的 TypeScript 项目是参考。

1. 取出来的 card 还是原来的字典

一开始我没明白，为什么先写一句 card = cards.get(card_id)。如果编号存在，card 和 cards[card_id] 指向同一个卡片字典，所以改 card["answer"]，从原来的 cards 里也能看到变化。如果编号不存在，get 返回 None，得先检查再读状态。

2. 第二次返回 False，是因为卡片已经回答了

我最开始只保存了答案，忘了把状态从 open 改成 decided，下次就还会把它当作待回答的卡片。后来我又把两次调用写成了不同编号。想看重复回答会怎样，两次都得传同一个编号。

我还问过第二次的 False 是不是因为答案为空。像第二次给同一张卡片传“绿色”，文字有内容，但函数先检查到卡片已经回答了，就会返回 False。对还在等待的卡片，None 和全空格要分别处理。全空格可以先用 strip() 去掉两头的空白，再检查结果是不是空字符串。这段空白检查参考了老师的示范。

3. 回答成功才加一项任务

我一开始写的是 pending_tasks.add(card_id)。这里用的是列表，要写 append。而且后续处理要知道卡片编号和答案，所以放进去的是整个任务字典。

这样同一张卡片再答一次，按代码逻辑就不会多加一项。今天贴出了回答和入队代码，老师帮我看了逻辑。我跳过了测试，所以还没有运行结果能确认。

4. 保存队列时，indent 管的是排版

最后开始把队列写到 JSON 文件。老师给的思路是先用 json.dumps 把列表转成字符串，再用 Path.write_text 写进去。我问了 indent 是干什么的。比如 indent=2 会把内容按层级缩进，方便打开文件看，读回来的数据还是一样的。

我做到了保存函数的练习，最终文件内容还没核对。下次先打开 JSON 看里面有没有预期的一项任务，再试着把列表读回来。
