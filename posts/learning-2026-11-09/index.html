3. Skill不等于另外造了一个Agent

今天让 AI 帮我做了一个“总教师”技能，用来统一学习路线，再安排具体的小课。

后来我追问它到底靠什么实现，才把这件事说清楚：目前主要是教学规则、参考资料和学习记录文件，执行时借用现有工具。并没有因为起了“总教师”这个名字，就另外开发出一套独立运行的教师系统。

Skill 可以理解为可复用的做事方法。简单的 Skill 主要是提示词和说明，复杂一点也可以带脚本、模板和资料。它告诉执行者怎么做，但文件放在那里，并不意味着任务已经开始执行。

4. Agent、Harness和Bot不是三个互斥的东西

我最开始的问题是：Agent 是不是比 Skill 多几个程序来监督调用？后来发现不能只按程序数量来区分。

Agent 的重点在于根据目标和执行结果，决定接下来做什么。例如读取学习记录之后，判断应该复习、练习，还是进入下一课。

Harness 是支撑这个过程的运行框架。它可以把信息交给模型，执行模型选出的工具调用，再把结果传回去，也可以管理状态、限制、暂停和恢复。它通常是 Agent 系统的一部分，不是旁边又站了一个监督机器人。

Bot 则是“机器人服务”的叫法。固定收到一句话就回复一句话，也可以叫 Bot；背后接了模型和工具、能推进任务的，也可以叫 Bot。

所以 Bot 不能直接等同于前端，Bot 和 Agent 也不一定是二选一。同一个产品可以既是 Bot，又采用 Agent 的工作方式。这些词在不同项目里用法也会有差别，还是得看实际能做什么。

5. 产品做得好，不一定是发明了新概念

聊到 Grok Bot 时，我一直想问的是：既然它也是 Agent，为什么还会引起关注？

这里可以从产品角度想一下。用户不一定关心底层叫 Agent 还是 Harness，更多是看入口是否方便、工具有没有接好、任务能否真的完成。

把已有能力组合成一个能直接使用的产品，也有价值。不过这只是解释产品吸引力的一种思路，不能直接当成它实际走红原因的结论。真正使用时，还要看成功率、成本，以及失败以后能不能恢复。

6. 接下来的学习方向

今天确定用 agent-autoloop 作为研究项目：读原来的 TypeScript 源码，再在单独的 Python 学习项目里实现核心机制，同时想清楚每个功能解决什么用户问题。

Python 学习项目和给原仓库贡献代码是两件事，不能把自己写了一个 Python 版本，就记成给 TypeScript 原项目贡献了 PR。

现在先把后端基础和更新功能做好，再逐步学模型调用、工具调用、调度和暂停恢复。今天这些主要是概念梳理和路线确定，不能算已经独立实现了 Agent 系统。
