今天先体验了一遍 agent-autoloop，再看一点相关代码。另一边还整理了交换机实验和算法课程报告。把实际做到的、老师演示的分开记一下。

## 1. 先体验提问和继续执行

这次用了一个选颜色的小任务。程序提出问题，我选择蓝色，回答交回去以后，任务继续执行，最后显示完成。后来接了飞书，我在卡片上点击，也走通了这个过程。

这里要记清楚：这轮用的是固定脚本演示 Agent，没有调用真实模型。前面尝试真实模型时连接出了问题，任务超时，所以不能说模型已经接好了。

老师讲的一个重点是，等待我回答的时候，Agent 的上一轮可以先结束。问题和等待状态由中台保存，我回答以后，再把答案交给新一轮。这里的“继续”不一定是同一个进程一直挂着等。

我还问了手机能不能派任务。收到卡片、回答卡片和发起新任务，是不同的入口。飞书里能点回答，并不等于已经有一个手机端的完整任务管理页面。

## 2. 架构图简单，交接规则不简单

我看到架构图时问，这个项目就这么简单吗？图上可以先看三个角色：中台记状态和派任务，Worker 领任务并启动 Agent，Agent 执行或者提问。

但是一条“回答后继续”的箭头，实际还有不少问题：点两次会不会执行两遍？等回答时程序重启怎么办？新一轮怎么拿到上一次的答案？

这些才是后面要沿着源码看的内容。目前我体验了流程，也看了讲解，还没有自己写出这套机制。

## 3. 命令行参数先取出来，再拆开

今天我在终端实际运行了这个例子：

```javascript
console.log(['node.exe', 'agent-autoloop.ts', 'why', '2'].slice(2));
// [ 'why', '2' ]
```

`.slice(2)` 从下标 2 开始取，前面的运行程序和脚本路径就不在结果里了。这里的 `'2'` 还是字符串。

老师随后用这行解释命令和参数怎么分开：

```javascript
const [command, ...args] = ['why', '2'];
// command 是 'why'，args 是 ['2']
```

读到回答卡片的代码时，两个编号也要分清。比如 `answer 1 1`，前一个是卡片编号，后一个是显示给人的选项序号。源码把第二个数减 1，交给中台的就是 `choice: 0`。

对象里的三个点又是另一种使用场景。老师给的对照例子是：

```javascript
const option = { choice: 0 };
const body = { card: 1, ...option };
// { card: 1, choice: 0 }
```

Python 可以写成 `body = {"card": 1, **option}`。这部分我还需要结合功能练习，不能因为看过例子就算会了。

对应源码：[agent-autoloop 的命令入口](https://github.com/KKKKhazix/agent-autoloop/blob/d6b2391293c66b3c219b6cfa3a4495772ad9c1a7/cli/main.ts)。

## 4. 交换机实验要让配置和结果对得上

今天还让 AI 协助完成了 Packet Tracer 的交换机实验和报告。搭拓扑、配置、验证和截图主要由 AI 操作，这里记录材料里的结果，不算我已经独立完成了配置。

实验用了两台交换机和四台 PC。任务书正文要求 VLAN 300、500，图中却写着另一组编号，最后按正文配置，并在报告里说明差异。交换机之间用 Trunk 连接，记录中 PC0 到 PC2 的 Ping 是发送 4 包、收到 4 包，丢包率 0%。这个结果只说明所测的这条连通路径通过了。

我要求再次逐项检查。复核时发现上一版截图太小、基本配置命令不够详细，随后补了命令、放大截图，也重新打开保存的工程核对配置。只有一张成功截图还不够，端口、VLAN 和实际保存的工程也要对应。
