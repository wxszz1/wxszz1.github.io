今天先把 Python 工单练习收尾，然后第一次在这份练习里接真实模型和只读工具。工单流程参考了 agent-autoloop，代码写在单独的 Python 项目里。

## 1. 没有卡片可答的时候，队列里可能还有活

今天我按需求自己改了命令行的行为。没有卡片可答，就提示并回到菜单。队列空了也是一样。这两个入口得各自判断，因为卡片全答完的时候，之前入队的活还可能等着处理。

导师在临时目录复跑了一次。有效回答新增一条待办。重启后再回答同一张卡片，原答案没有被盖掉，队列也没多一条。两张卡片都答完后，仍然能处理队列里的两条任务。再重启，答案还在，处理过的任务也没有回来。顺便检查了空操作，没有新建状态文件或改动原文件的修改时间。

## 2. 接上真实模型后，先看能不能正常收发

我用一条关于 Python `strip()` 的笔记做输入，本机运行后收到了模型回复。直接回车和只输空格会在发请求之前被拦住。用无效测试密钥试了一次，程序给出了 `AuthenticationError`。这样遇到没内容和认证失败，至少能分清卡在哪一步。

## 3. 模型发出工具请求，真正读文件的是 Python

模型可以请求“读取关键笔记”，但执行工具的是我的程序。程序拿到请求后读文件，把结果交回模型，模型再用这些结果回答。跑过的几种情况里，有关键笔记时回复能引用读到的内容，读到零条时就报告这个结果，文件损坏时提示读取失败。未知工具的拒绝行为由导师用替身验证。

目前工单恢复和模型工具调用是分别验收的。接下来还要把它们串起来，试试模型提出问题后退出程序，重启回答，再继续检索。今天的代码有本地提交记录，提交操作由导师代办。
