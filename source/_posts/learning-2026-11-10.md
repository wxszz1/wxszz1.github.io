今天继续做阅读清单后端，把修改文章这条链路接起来，又开始看 agent-autoloop 的源码。东西不少，先把几个实际遇到的问题记下来。

## 1. 更新功能要从业务函数接到客户端

昨天还在看更新文章的示例，今天在老师提示下逐步写了业务函数、更新接口、客户端函数和菜单。

业务函数负责查找文章、校验标题和链接，再修改数据；接口负责接收请求、把错误变成 HTTP 响应，并在成功时保存。客户端则用 `httpx.put()` 发送请求。

这几个地方虽然都是“修改文章”，负责的事情不一样。不能业务函数写完了，就认为整个操作已经能用了。

检查重复链接时还要排除自己。保留原链接、只修改标题应该成功；改成另一篇文章的链接才应该报错。

## 2. 测试不只是看成功时有没有返回值

今天补了更新成功、重复链接失败、保留原链接，以及接口成功和文章不存在的测试。

成功时要看标题和链接有没有修改，ID 和已读状态有没有保留。失败时除了检查报错，还要检查原来的数据有没有被改坏。

这里用到了 `deepcopy`，可以先保留一份独立的数据快照。执行失败后，再比较整个列表是否和原来一样。普通赋值只是让两个变量指向同一个对象，不能拿它当独立快照。

接口测试又比业务函数测试多了一层：请求是不是真的进了接口，状态码是否正确，数据是否保存，都要考虑。

## 3. 接口测试不要写进真实数据文件

今天接触了 `TestClient`、`tmp_path` 和 `monkeypatch`。最开始看到测试函数的参数，还不太明白这些东西从哪里来。

`tmp_path` 是 pytest 提供的临时目录，测试可以在里面准备 JSON。`monkeypatch` 可以把接口模块的 `DATA_FILE` 临时指向这个文件，结束后恢复。

这样测试的还是实际接口，但不会把自己的文章数据改掉。`TestClient` 是进程内请求，也不代表已经验证了真实端口和网络连接。

两个接口测试里重复准备文章列表，后来又提取成了一个简单的 fixture：

```python
@pytest.fixture
def sample_articles():
    return [{"id": 1, "title": "原标题", "url": "https://example.com/1", "is_read": False}]
```

测试函数通过同名参数取得它。这里主要是理解 pytest 如何提供测试数据，还不能说自己已经能独立设计复杂 fixture。

## 4. 同名的异常类，不一定是同一个类型

今天遇到一个很具体的问题：希望文章不存在时返回 404，测试却得到了 400。

业务文件里已经有：

```python
class ArticleNotFoundError(ValueError):
    pass
```

我又在接口文件里定义了一个同名的类。名字虽然一样，但这是两个不同的类型。业务函数抛出的那个，接口里自己定义的同名异常接不住，最后落到了 `ValueError` 分支。

修正方法是保留业务文件里的定义，在接口里导入它：

```python
from articles import ArticleNotFoundError
```

捕获时也要把子类放在父类前面：

```python
except ArticleNotFoundError as error:
    raise HTTPException(status_code=404, detail=str(error))
except ValueError as error:
    raise HTTPException(status_code=400, detail=str(error))
```

因为这个自定义异常本身也属于 `ValueError`，父类放前面就会先接住它。

修正后，老师最近一次核验是 20 项测试通过，还有一条依赖弃用警告。后续有些修改由我自己验证，不能把之前的结果当成所有后续改动都已通过。整个过程有示范和提示，跟着写通和独立迁移还要分开看。

## 5. 开始读原项目，先看入口

今天把 [agent-autoloop](https://github.com/KKKKhazix/agent-autoloop) 克隆到了本地。阅读依据是提交 `d6b2391293c66b3c219b6cfa3a4495772ad9c1a7`。

原项目要求 Node 24 以上，环境切换到 Node 24.14.0 后，版本和帮助命令能运行。

先从 `package.json` 找命令对应的启动文件，再看启动文件导入的 `cli/main.ts`。里面有这样一行：

```typescript
const [command, ...args] = process.argv.slice(2);
```

例如输入 `status --json`，前两个参数是 Node 和脚本路径，`slice(2)` 去掉它们。剩下的第一个元素交给 `command`，其余收进 `args`。

它只是取出输入，后面还要查命令表、执行对应函数。

看到八百多行的文件时，我觉得有点长，就让老师按功能做了阅读地图。先看“输入参数→命令表→执行”这一小段，其他模块遇到再查。这里是拆阅读范围，没有实际重构原仓库。

## 6. 能输出帮助，不等于整个项目全部正常
